# Repository Structure

```
jolt/                   Jolt Physics, a submodule pinned to the release kolt binds
c/                      the C API over Jolt, and how it's built
kotlin/kolt/            the Kotlin Multiplatform module
desktop/                the JVM's native runtime: the loader, and libkolt in a jar per platform
build-logic/            the generator, and the Gradle tasks that run it
docs/                   this documentation
.github/                CI, the release and docs workflows, issue and pull request templates
```

Most of the repository is generated and committed. Generated files start with a `Generated by …; do not edit.` line;
[`./gradlew apiCheck`](generator.md#keeping-it-honest) fails if any of them isn't what the generator would write.

## `c/`

| Path | Written by | What it is |
| :--- | :--- | :--- |
| `api-headers.txt` | hand | Which Jolt headers are API, and what in them is left out. The generator's input. |
| `kolt/generated/` | `generateCApi` | The C API: a `.h` and `.cpp` per class, grouped as Jolt's directories (`physics/body/JphBody.h`), plus `Types.h`, `Bridge.hpp`, `Includes.hpp`. |
| `kolt/manual/` | hand | C for what the generator can't map, and for what a plain forwarder gets wrong: a function declared here replaces the generated one of its name (`JphJoltManual`). And `JphBridge.hpp`, the helpers only Jolt can write. |
| `kolt/jni/` | hand | The hand-written half of the JNI layer (`KoltJni.cpp`) and the linker script that exports only JNI entry points. |
| `kolt/web/` | hand | `kolt-globals.js`, which installs the wasm's exports as the globals Kotlin's externals bind. |
| `api-manifest.json` | `generateCApi` | Each C function's ABI signature, by header. What the Kotlin stages read. |
| `api-coverage.txt` | `apiCoverage` | Every function the C++ API calls for: wrapped, not yet, or why not. |
| `CMakeLists.txt` | hand | Builds Jolt and the C API for every target. See [Native Builds](native-builds.md). |

## `kotlin/kolt/`

One module, `io.github.erkko68.kolt`, with these source sets:

| Source set | What's in it |
| :--- | :--- |
| `commonMain` | The whole public API. |
| `nativeMain` | `interop` for Kotlin/Native (iOS): arrays pinned, C called directly. |
| `jniMain` | `interop` for the JVM and Android, which share JNI: `KoltJni`, arrays copied. |
| `jvmMain`, `androidMain` | How each loads `libkolt`: `KoltLoader`, or the app's native libraries. |
| `webMain`, `jsMain`, `wasmJsMain` | `interop` for the web, and `loadJolt()`. |
| `commonTest` | The tests, run on every target. See [Testing](testing.md). |

Inside `commonMain`, packages follow Jolt's directories:

| Package | Written by | What it is |
| :--- | :--- | :--- |
| `<group>.capi` (`physics.body.capi`) | `generateKotlinExternals` | One `external fun` per C function. Internal plumbing. |
| `<group>` (`physics.body`, `core`, `geometry`, …) | `generateKotlinApi` | The typed classes over the externals: the public API. |
| `math` | hand | `Vec3`, `Quat`, `Mat44` and the rest: data classes mirroring Jolt's math types. |
| `interop` | hand | `NativePointer`, `NativeObject`, `InteropScope`, upcalls: what the generated code is written against, `expect`ed per platform. |
| (root) `JoltRuntime.kt` | hand | `Jolt.init()` and `Jolt.shutdown()`. |

## `build-logic/`

An included build, so the generator is compiled before the main build configures.

| Path | What it is |
| :--- | :--- |
| `src/main/kotlin/kolt-root.gradle.kts` | The root project's plugin: **everything the generator is told about Jolt**, as one `ApiGenConfig`. |
| `src/main/kotlin/buildlogic/apigen/` | The generator. Knows no library. See [The Generator](generator.md). |
| `src/main/kotlin/buildlogic/emsdk/` | `setupEmsdk`, which installs the pinned Emscripten SDK. |
| `src/test/fixture/` | A small C++ library (`geo`) and the committed output of every stage run on it. |
| `src/test/kotlin/` | `FixtureTest`, which runs the generator on the fixture and compares. |

## Not committed

| Path | What it is |
| :--- | :--- |
| `build/generated/bindings/` | The JNI forwarders and wasm export tables (`generateBindings`): derived from the manifest at build time. |
| `build/cmake/<target>/` | CMake's build directories. |
| `build/kolt-c/<target>/` | iOS's static libraries. |
| `desktop/build/kolt-c/<os>-<arch>/` | The host's JNI library. |
| `.emsdk/` | The Emscripten SDK. |
